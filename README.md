## 🚀 เริ่มใช้งานใน 3 นาที

ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน **20.19 ขึ้นไป**

```bash
npm install     # ติดตั้ง
npm run build   # สร้างหน้าเว็บ
npm start       # เปิดเซิร์ฟเวอร์
```

เมื่อเปิดสำเร็จ หน้าต่างจะแสดงที่อยู่ให้ เช่น

```text
  เครื่องนี้:      http://localhost:8787
  WiFi เดียวกัน:  http://192.168.1.23:8787
```

ให้มือถือทุกเครื่องต่อ **WiFi หรือฮอตสปอตเดียวกับโน้ตบุ๊ก** แล้วเปิดที่อยู่ `WiFi เดียวกัน`
(หรือเปิดห้องแข่งบนโน้ตบุ๊ก แล้วให้มือถือสแกน QR ระบบเลือก IP ของ WiFi ให้เอง)

> 💡 ใช้ผ่าน `http` บน LAN ได้ปกติ การจับเวลาและการบันทึกในเครื่องทำงานครบ
> มีเพียงฟีเจอร์ที่เบราว์เซอร์จำกัดไว้ให้เฉพาะ `https` (กันจอดับ, แชร์, เปิดแบบออฟไลน์) ที่จะปิดไปเงียบๆ

หัวใจของระบบมี 4 ข้อ

### 1️⃣ ทุกการกระทำคือ "event" ที่แก้ไม่ได้

| event | ความหมาย |
|---|---|
| `start` | ปล่อยตัวทั้งรอบ |
| `stop` | นักวิ่งเข้าเส้นชัย |
| `cancel` | ยกเลิกนักวิ่ง |
| `void` | ย้อนกลับ event ใดก็ได้ (คือปุ่ม "แตะผิด" / "เอาคืน") |

ผลการแข่งขันคำนวณจาก *เซตของ event* ด้วยฟังก์ชันบริสุทธิ์ [`fold()`](src/race.ts)
ดังนั้น **ลำดับที่มาถึง ข้อมูลซ้ำ หรือข้อมูลที่มาช้า ไม่ทำให้ผลเปลี่ยน**
ทุกเครื่องที่มี event ชุดเดียวกันจะแสดงผลเหมือนกันเป๊ะ (มีเทสต์สุ่มลำดับ 200 รอบยืนยัน)

### 2️⃣ Local-first

[`Room`](src/room.ts) เขียน event ลง `localStorage` **ก่อน** แตะเครือข่ายเสมอ
ทุกครั้งที่ต่อติด เครื่องจะดาวน์โหลด event ที่ตัวเองขาด และอัปโหลด event ที่ relay ขาด
แม้ relay รีสตาร์ทจนข้อมูลหาย **อุปกรณ์ก็สร้างข้อมูลคืนให้เอง**

### 3️⃣ Relay โง่โดยตั้งใจ

[`server.js`](server.js) ทำแค่ 3 อย่าง: ตรวจข้อมูล → เก็บต่อท้ายไฟล์ `data/<รหัส>.jsonl` → กระจายให้ทุกเครื่องในห้อง
ตรรกะการแข่งทั้งหมดอยู่ฝั่งเครื่อง จึงไม่มีอะไรให้พังที่ศูนย์กลาง

### 4️⃣ นาฬิกาที่เชื่อถือได้

- แต่ละเครื่องวัด offset กับนาฬิกาของ relay แบบ NTP (ping ทุก 4 วินาที เลือกตัวอย่างที่ round-trip ต่ำสุดจาก 8 ครั้งล่าสุด)
- เวลาที่บันทึกคือ **จังหวะที่นิ้วแตะจอ** (`pointerdown`) ไม่ใช่ตอนปล่อยนิ้วหรือตอนข้อมูลถึงเซิร์ฟเวอร์
- กดตอนยังไม่เคยซิงก์ (เช่น จุดอับสัญญาณ)? เก็บเวลาดิบไว้ แล้วแปลงเป็นเวลากลางทันทีที่ซิงก์ได้
- ทุกผลมี **± ความคลาดเคลื่อน** กำกับ ไม่โกหกผู้ใช้

เวอร์ชันก่อน (Next.js บน Vercel + Upstash Redis) ติดปัญหาที่แก้ปลายเหตุไม่จบ

| ปัญหาเดิม | ต้นเหตุ | สถาปัตยกรรมใหม่ |
|---|---|---|

| ผูกกับ Vercel + Redis | ต้องใช้คลาวด์สองเจ้า | Node process เดียว รันได้ทุกที่ |

## 🌐 นำขึ้นอินเทอร์เน็ต

ใช้โฮสต์ใดก็ได้ที่ **รัน Node และรองรับ WebSocket** เช่น Render, Railway, Fly.io หรือ VPS

| ตั้งค่า | ค่า |
|---|---|
| Build command | `npm install && npm run build` |
| Start command | `npm start` |
| `PORT` | พอร์ตที่ใช้ (โฮสต์ส่วนใหญ่ตั้งให้เอง, ค่าเริ่มต้น `8787`) |
| `DATA_DIR` | ที่เก็บไฟล์ข้อมูล (ค่าเริ่มต้น `./data`) |

> ⚠️ **รันเครื่องเดียว (1 instance) เท่านั้น** เพราะทุกห้องอยู่ใน process เดียว
>
> ✅ ดิสก์ของโฮสต์ฟรีมักหายเมื่อรีสตาร์ท ไม่เป็นไร เพราะอุปกรณ์จะอัปโหลดข้อมูลคืนให้เองเมื่อต่อกลับ
>
> ❌ **Vercel ใช้กับ relay ไม่ได้** (serverless ไม่รองรับ WebSocket)
> ถ้าอยากวางหน้าเว็บบนโฮสต์ static ให้ build ด้วย
> `VITE_RELAY_URL=wss://<relay ของคุณ>/ws npm run build`

ถ้าใช้โฮสต์แพ็กเกจฟรีที่ "หลับ" เมื่อไม่มีคนเรียก HTTP แอปจะเรียก `/health` เพื่อปลุกให้อัตโนมัติ
แต่ควรเปิดแอปก่อนรายการแรกสัก 2 นาที (รายละเอียดใน [แผนทดสอบภาคสนาม](docs/FIELD-TEST.md))

## 🧪 พัฒนาและทดสอบ

```bash
npm run dev        # relay + Vite (hot reload) ที่ http://localhost:8787
npm test           # เทสต์ทั้งหมด (ต้องใช้ Node 23.6+ ที่รัน TypeScript ได้เอง)
npm run typecheck  # ตรวจชนิดข้อมูล
npm run check      # typecheck + test + build ทีเดียว
```

เทสต์แบ่งเป็น 3 ชุด

| ไฟล์ | ทดสอบอะไร |
|---|---|

- 🔑 **รหัสห้องคือกุญแจ** ใครรู้รหัสก็เข้าร่วมและแก้ผลได้ เหมาะกับกีฬาสี ไม่เหมาะกับการแข่งชิงรางวัลเงิน
