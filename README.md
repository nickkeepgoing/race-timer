# จับเวลาวิ่ง — ระบบจับเวลาสองจุด

เว็บสำหรับจับเวลาวิ่งโดยแยกอุปกรณ์เป็นจุดเริ่มกับเส้นชัย เวลาที่ใช้จริงคำนวณจาก
"นาฬิกาของเซิร์ฟเวอร์เพียงจุดเดียว" (ไม่ใช่นาฬิกาของมือถือแต่ละเครื่อง) ทำให้ตัดปัญหา
นาฬิกาสองเครื่องไม่ตรงกันทิ้งไปได้ทั้งหมด เหลือแค่ความหน่วงของเครือข่าย (ปกติหลัก
สิบมิลลิวินาทีถ้าใช้ WiFi วงเดียวกัน) ซึ่งแม่นยำกว่าการโบกมือให้กดนาฬิกาพร้อมกันมาก

หน้าเว็บมี 3 หน้า:
- `/start` — มือถือที่จุดเริ่ม กดปุ่ม "เริ่ม"
- `/stop` — มือถือที่เส้นชัย กดปุ่ม "หยุด"
- `/dashboard` — ดูผลทุกรอบ เรียงจากเร็วสุด ดาวน์โหลดเป็น CSV ได้

## วิธีอัปขึ้น Vercel

1. อัปโหลดโฟลเดอร์นี้ขึ้น GitHub repo ใหม่ (หรือลาก-วางไฟล์ผ่านหน้า vercel.com/new ก็ได้
   ถ้าไม่อยากใช้ Git)
2. ไปที่ [vercel.com/new](https://vercel.com/new) แล้วเลือก import repo นี้ (Next.js
   จะถูกตรวจจับอัตโนมัติ ไม่ต้องตั้งค่าอะไรเพิ่ม) กด Deploy
3. **สำคัญ**: ต้องเพิ่ม Redis store ให้โปรเจกต์ ไม่งั้นจุดเริ่มกับเส้นชัยจะไม่เห็น
   สถานะของกันและกัน (เพราะ Vercel รันแต่ละ request บนเครื่องคนละตัว ข้อมูลในหน่วยความจำ
   จะไม่ถูกแชร์กัน)
   - ในหน้าโปรเจกต์บน Vercel ไปที่แท็บ **Storage** → **Create Database**
   - เลือก **Redis** (ผ่าน Marketplace ของ Vercel เช่น Upstash) แล้วเชื่อมกับโปรเจกต์นี้
   - Vercel จะตั้งค่า environment variables ที่ชื่อขึ้นต้นด้วย `KV_REST_API_...`
     ให้อัตโนมัติ — โค้ดอ่านตัวแปรพวกนี้เองผ่านแพ็กเกจ `@vercel/kv` ไม่ต้องแก้โค้ด
   - กด Redeploy อีกครั้งหลังเชื่อม database เสร็จ
4. เปิดลิงก์ที่ได้บนมือถือ 2 เครื่อง เครื่องนึงเปิด `/start` อีกเครื่องเปิด `/stop`
   แล้วเปิด `/dashboard` บนเครื่องที่ 3 (หรือโน้ตบุ๊ก) เพื่อดูผลรวม

### ถ้ายังไม่เชื่อม Redis

แอปยังรันได้และหน้าตาใช้งานได้ปกติ แต่ `/start` กับ `/stop` จะไม่เห็นสถานะของกัน
เพราะข้อมูลถูกเก็บแยกเครื่องต่อ request บน Vercel — ต้องเชื่อม Redis ตามข้อ 3 ก่อน
ใช้งานจริงเสมอ (รันทดสอบบนเครื่องตัวเอง `npm run dev` ได้โดยไม่ต้องมี Redis เพราะ
ใช้หน่วยความจำในเครื่องแทนชั่วคราว)

## รันทดสอบในเครื่องตัวเอง

```bash
npm install
npm run dev
```

เปิด `http://localhost:3000`

## ข้อจำกัดที่ควรรู้

- ต้องมีสัญญาณอินเทอร์เน็ต/WiFi ทั้งสองจุด ถ้าสัญญาณหลุดกลางรอบ ให้กด "ยกเลิกรอบนี้"
  ที่หน้า `/start` แล้วเริ่มใหม่
- รองรับจับเวลาทีละ 1 รอบเท่านั้น (กดเริ่มรอบใหม่ไม่ได้จนกว่ารอบก่อนจะหยุด) เหมาะกับ
  การคัดเด็กทีละคน/ทีละเลน
- ความแม่นยำขึ้นกับความหน่วงเครือข่าย แนะนำให้ทั้งสองเครื่องต่อ WiFi เดียวกัน
  (เช่น ปล่อยฮอตสปอตจากโน้ตบุ๊ก) เพื่อความแม่นยำสูงสุด
